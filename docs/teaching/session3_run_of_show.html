Session 3 Run-of-Show — Sim-to-Real

Instructor minute-by-minute · 3 hours · one robot + one 3080 per group · retrains on the RTX 6000s

The one thing to protect: every group must complete one full loop — deploy on the real robot → measure the gap → apply a fix → redeploy. Everything else is optional. If you're behind, cut the second iteration, not the measurement.

Before students arrive (T−45 to T−0)

  • Robots: charged, zero-calibrated the night before, and pre-loaded with the gold walk checkpoint. Power each one and confirm it holds a stand yourself — don't discover a dead motor in front of students.
  • Sim baseline logged: pre-record a sim rollout of the gold policy for each robot config and note the file path — groups need it to overlay against real (see gotcha below). This is the #1 thing people forget.
  • Benches: safety stand + harness per bench, kill switch tested, floor zone taped off, cables dressed.
  • GPUs: 6000 retrain queue empty and ready; have 1–2 pre-trained domain-randomization-widened variants on disk as drop-in fixes so nobody waits on a from-scratch run.
  • Paper: printed cheat sheet + lab sheet per group. One backup robot on standby.

Gotcha playbook

Half the robots won't stand

  • Fastest triage, in order: (1) confirm the kill switch is released; (2) re-run calibrate_zero.py; (3) reseat the suspect leg's cable; (4) check one motor with examples/test_dynamixel.py.
  • If it's not up in ~3 min, swap to the backup robot or pair the group with a neighbor — don't let one dead servo eat the session.
  • A down-robot group can still do all the science on a partner's recording — the analysis is the point.

The gold policy still falls on the real robot

  • 90% of the time it's calibration — re-zero and confirm a clean stand first. A few degrees of ankle offset topples a walk.
  • Then reduce difficulty: command a slower walk (smaller command), check harness height (too low = it can't load its legs; too high = it hangs).
  • Confirm the robot is running its correct config and the intended checkpoint, not a neighbor's.
  • Reframe for the group: a policy that falls but whose overlay explains why is a full success today.

sim2real_eval.py won't run / "nothing to compare against"

  • Root cause is almost always a missing sim baseline. This is why you pre-recorded a sim rollout per config — hand out that exact path.
  • Check the real recording actually saved from Hour 1 (the --record flag and output dir). No file = redeploy a quick 10-second rollout.
  • Keep a known-good example pair (sim + real logs) on hand so a blocked group can still practice reading an overlay while you debug theirs.

Retrain queue jammed (only 4 GPUs)

  • Most fixes are calibration/gain = no retrain. Actively steer groups there; only queue genuine domain-rand cases.
  • Serve your pre-trained DR-widened variants as instant drop-ins instead of from-scratch runs.
  • Batch identical configs into one run; time-box any live retrain to what finishes before 2:00.

Running behind

  • Cut, in order: the 2nd iteration (2:25) → the sim re-test (0:40, if a group already trusts it) → trim demos to 90 s.
  • Never cut: the first real deploy+record, and the overlay. That's the loop.

Staffing & definition of done

Two instructors if possible: a floor lead (safety, robots, calibration) and a GPU lead (owns the 6000 retrain queue and copies checkpoints to group machines). Solo? Recruit one confident student as your "GPU operator."

Done when every group has: a recorded before/after on the real robot, a filled diagnose table, and can say in one sentence which knob they turned and why. A perfect walk is a bonus, not the bar.
